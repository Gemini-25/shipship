**지금: v10.10(선내 로봇·자원 회복) · v10.11(조리사·배급) · v11.0(예방) 첫 판 · v11.2(엔진·항로, 사고 종류 15가지 + 무작위 사고)까지.** v10.12(칸막이 철거·설비 옮기기) · v11.1(분산 운영) · v11.2 교신(조난 신호·보급·구조) 첫 판. 남은 것: v11.3 승무원 성장.
v11.1 분산 운영, v11.2의 외부 교신(조난 신호·보급·도킹), v11.3 승무원 성장. 그 앞의 기록 — **v10.3(신뢰성)까지 끝남.** 검토(v10.2 코드 검토 메모)를 받아 뒤의 순서를 새로 짰다 — 새 기능을 늘리기 전에 저장·되감기·개조의 정합성을 다지고,
그다음 **자원 회복 → 대인원 생활 → 공간 개조 → 예방 → 분산 운영 → 항로·교신 → 승무원 성장** 순서로 간다. 결과와 근거는 `PROGRESS.md`.
한 단계는 대략 한두 번의 작업 주기 분량입니다 (사람 기준 일정이 아니라 이 프로젝트의 작업 단위).

## 지키는 원칙

1. **사고는 첫 충격만 만든다.** 그다음(감압, 격벽, 정전, 발견 지연, 대응)은 전부 각 시스템이 처리한다. 사고 해결 스크립트는 만들지 않는다.
2. **새 시스템은 순환 의존과 비상수단이 있을 때 들인다.** "A가 B를 필요로 하고 B도 A를 필요로 하는데, 그 고리를 끊는 비상수단 C가 있다"
   (원자로 ↔ 냉각 펌프 ↔ 배터리/보조 발전기처럼). 이 구조가 없는 시스템은 뒤로 미룬다.
3. **작은 규칙으로 지연을 만든다.** "감지기는 전기가 있어야 운다" 같은 규칙 하나가 이벤트 없이 더 큰 사고를 만든다.
4. **폭보다 깊이.** 운석·감압·화재·정전 네 가지가 서로 물렸을 때 실패, 장기 장애, 우회 대응까지 나오기 전에는 사고 종류를 늘리지 않는다.
5. **결과는 분포로 본다.** 모든 단계는 헤드리스 시나리오로 검증하고, "복구됐나"가 아니라
   "완전 복구 / 부분 복구 / 장기 장애 / 실패"가 어떤 비율로 나오는지를 본다.

## v3.1 정비와 실패 시험 ✅

새 기능 없이 지금 있는 것의 구멍을 막고, "다 복구된다"는 결과가 진짜인지 확인한다.

**구조 문제 수정**
- [x] **화재 작업 대상이 낡는 문제.** `FireIn(room, hottest, slot)`이 처음 가장 뜨거웠던 칸을 기억하고, `Post()`는 긴급도·설명만 갱신한다.
  불이 번지면 옛 위치로 간다. → `Post()`가 대상도 갱신하고, 작업을 짤 때와 분사할 때 현재 가장 가까운/센 불을 다시 찾는다.
- [x] **빈 목록 방어.** `Atmosphere`의 재가압 효율이 산소 발생기에 `Max()`를 바로 쓴다(0대면 예외).
  `DefaultIfEmpty(0f)`로 막고, `First()`·`Max()`·`Min()`을 빈 목록에 쓰는 곳을 전부 점검한다 (구획 사출·설비 파괴 대비).
- [x] **외벽 피로.** 지금은 용접하면 강도가 0.9~0.98로 돌아와서 반복 수리의 대가가 흔적뿐이다.
  → `MaxIntegrity`(용접할 때마다 내려감)를 두고, 피로한 벽은 같은 충격에 더 쉽게 뚫리게 한다. "다섯 번 용접한 벽은 새 벽이 아니다."

**극단 실패 시나리오** (헤드리스 `--scenario=`, 결과를 네 가지로 분류해 출력)
- [x] `nosuits` 우주복 두 벌 + 두 구획 동시 파공
- [x] `nosealant` 실링폼 두 개 + 큰 파공 세 곳
- [x] `keycrew` 기관장과 정비사가 부상 + SCRAM
- [x] `nofuel` 보조 발전기 연료 2시간 + 배터리 바닥 + 냉각 펌프 고착
- [x] `overload` 운석 둘 + 화재 둘 + 고장 셋이 동시에 (작업 12개 이상)
- [x] `secondhit` 공기 탱크를 다 쓴 뒤 두 번째 파공
- 이 중 몇 개는 **복구에 실패해야 정상**이다. 다 복구되면 그 자체가 v4에서 고칠 목록이 된다.

**사고 화면 위계**
- [x] 시각 강도를 치명 → 긴급 → 일반 세 단계로 나눈다. 평상시 화면은 그대로 둔다
- [x] 치명 상태인 방(진공, 화재)은 방 전체를 하나의 상태로 크게 표시하고, 그 방의 O2/CO2 같은 세부 수치와 겹친 배지는 숨긴다
- [x] 작업 목록은 긴급 작업을 묶어서 위에, 나머지는 접는다

**끝났다는 기준**: 기존 시나리오 11개 + 새 시나리오 6개가 돌고, 결과 분류표가 나온다. 평상시 90일은 계속 무사.
→ **결과**: 18개(구조 시나리오 `downed` 추가) 중 완전 8 · 부분 6 · 장기 장애 3 · 실패 1. 90일·30일×3 무사.

## v4 실패할 수 있는 우주선 ✅

지금 시스템만으로 실패·장기 장애·부분 복구가 자연스럽게 나오게 한다. 새 사고 종류는 넣지 않는다.

- **부분 복구 단계**: 설비 수리를 정지 → 긴급 우회(20%) → 부분 복구(60%) → 완전 복구로 나눈다.
  급하면 20%에서 멈추고 다음 일로 간다. 부품이 없으면 60%까지만 된다. (기획서의 "원자로 20% 출력 복구" 흐름)
- **구획 포기**: 실링폼·공기 탱크가 모자라면 새는 구역을 막는 대신 영구 격리한다 → **폐쇄 구역**으로 남는다.
  누가 그 결정을 하는지(가장 계급 높은 사람? 모두의 판단?)도 정한다.
- **사람의 한계**: 부상이 며칠씩 이어지며 작업 속도와 기술을 깎는다. 핵심 기술자가 다치면 서툰 사람이 대신 하다 실패한다.
  과로가 쌓이면 실수가 는다. 우주복 산소가 떨어져 가는 위기.
- **비상수단의 한계**: 보조 발전기 연료가 실제로 바닥날 수 있고, 냉각 여유가 적거나 서툴면 원자로 재기동이 실패할 수 있다.
  봉합이 실패하거나 떨어질 수 있다.
- **결정 필요**: 승무원 사망을 넣을지. 넣으면 실패가 진짜 무거워지고, 안 넣으면 "혼수·장기 부상"으로 대신한다.

**끝났다는 기준**: 무작위 사고 20회 헤드리스 실험에서 결과가 한쪽으로 쏠리지 않는다
(예: 완전 복구 50~70%, 부분·장기 장애 20~40%, 실패 5~10%). 사고가 없으면 여전히 90일 무사.
→ **결과**: 사고 한 번이면 완전 50% · 부분 40~45% · 장기 5% · 실패 0~5%(사망 켜면 5%).
하루 간격 세 번이면 완전 10% · 부분 40~45% · 장기 40~45% · 실패 0~10%. 평상시 90일 무사.
결정: **사망은 옵션**(`--death`), 기본은 꺼서 쓰러짐·장기 부상으로 대신한다.
덤으로 들어간 것: 숨 참고 뛰어들기(보관함이 진공 속일 때), 임시 침실, 진공에서 얼어 죽는 작물, 소화기 소모.

## v5 적응: 우회와 땜질 ✅

v4에서 드러난 가장 큰 구멍: **암흑 우주선**(보조 발전기 연료까지 바닥)에서는 펌프를 다 고쳐도 돌릴 전기가 없어 아무것도 못 한다.
그래서 전력 우회를 맨 앞에 뒀다. 기획서의 "임시 수리와 땜질", "우주선이 원래 설계와 다른 모습으로 변한다".

- [x] **암흑 우주선 탈출**: 연료통 급유, 채소로 바이오 연료(작업대도 전기가 필요 → 고리), 마지막 수단으로 **원자로 저출력 수동 기동**
  (제어봉 손으로, 자연 순환 냉각 7kW, 실패·화상·제어계 고장, 펌프 없이 오래 버티면 과열 정지)
- [x] **전력 우회**: 퓨즈가 없어 회로가 죽으면 살아 있는 회로에서 케이블로 임시 배선. 정격을 넘기면 달아올라 타거나 불을 낸다(화재와 물림).
  배선은 흔적으로 남는다
- [x] **카니발라이징**: 부품이 없으면 덜 중요한 설비를 뜯는다. 기준 = 전력 우선순위 + 방의 쓸모(포기한 구획의 설비부터) + 먹고 사는 설비는 아낌.
  뜯긴 설비는 멈춘 채 남는다
- [x] **전력 배분 결정**: 배터리가 빠지면 D → C → B 순으로 사람이 회로를 내린다(A는 절대 안 내림, 감압·불이 난 방의 회로도 안 내림).
  여유가 생기면 되올리고, 모자라면 배터리가 버티는 동안만 올리는 윤번 정전
- [x] **방 용도 변경**: 침실을 포기한 지 6시간이 넘으면 휴게실(→ 식당 → 의무실…)에 간이침대를 놓아 임시 침실로
- [x] 덤: 소모품 배급(모자라면 핵심 설비에만), 격벽 수동 폐쇄(전기 없는 문), 격벽 해제 직후 재잠금 떨림 제거
- [ ] **수리·자원 철학**: 리뷰어와 논의한 재료 티어와 임시 저티어 장비. 세부 안을 받으면 `Adaptation.cs` 옆에 넣는다 (빈자리로 둠)

**끝났다는 기준**: 부품이 바닥난 상태로 60일을 돌렸을 때 우주선이 "다른 모습으로" 살아남는다
(우회 배선, 뜯긴 설비, 폐쇄 구역, 용도가 바뀐 방이 실제로 생긴다).

## v8 외부 작업과 구조 분리 ✅ (리뷰어 문서 9~12, 14)

원칙 2: 외부 작업은 우주복·드론(충전·정비)과 물리고, 구획 분리는 구조 연결부와 물린다.
연결부를 이으려면 밖으로 나가야 하고(드론·EVA), 드론은 승무원에게 전기·부품·자재를 받아야 하고, 사람이 나가려면 에어락과 우주복(공기 탱크)이 있어야 한다.

- [x] **구조 연결부**: 방마다 2~6개, 하중과 피로, 외벽 5단계 "구조 연결 상실"(실링폼으로 못 막음), 다 끊기면 방이 실제로 떨어져 나간다(격자에서 빠지고, 이웃 벽이 찢기고, 열린 문으로 공기가, 뜯긴 전선·배관·환기관, 사람은 밖으로)
- [x] **EVA와 외부 드론**: 검사 · 수리 둘 · 견인 · 건설 드론 다섯 대, 에어락의 거치대 둘(충전·정비·자재 보급). 드론이 없으면 우주복 EVA
- [x] **구획 사출**: 대피 → 회수 → 전력·배관·환기 차단 → 격벽 용접 → 연결 해제(드론·EVA, 아니면 폭발 볼트) → 사출. 끌 수 없는 불도 사출 대상
- [x] **떨어진 방 되찾기**: 회의 → 견인 → 계류 → 임시 도킹 → 되살릴지 회의 → 연결부 보강 → 전력·배관·환기 재연결, 두 번 부결되면 잔해로 두고 부품만 회수
- [x] 덤: 공기 탱크로 우주복 보충, 배전반을 잃으면 전 회로 정전, 대신할 게 없는 방(배전반·하나뿐인 해치)은 무서워도 되찾는다, 구조 교훈 둘, 연결부 증설 개조

**끝났다는 기준**: 구조 사고의 결과가 한쪽으로 쏠리지 않는다 (버팀 · 사출 · 뜯겨 나감 → 되찾음/잃음).
→ **결과**: 구조 게이트 20회 버팀 65% · 되찾아 되살림 10% · 계류 10% · 잃음 15% (갈래 넷). 사출은 게이트에서는 "준비 중에 먼저 뜯겨 나감"으로 끝나고,
시나리오(`jettison`)에서만 끝까지 간다. 사고 종류 게이트는 운석 많은 배가 처음보다 높은 지표를 못 만들어 미달 → v9

- [x] 방이 떨어져 나갈 때 문을 먼저 닫은 뒤 손상을 계산해 열린 문과 닫힌 문이 같던 것

## v10.10 자원 회복

- 공기·실링폼·냉각수·금속판의 생산·소비 기록 (사고마다, 하루마다), 상황별 비축 목표 (평시 / 사고 직후 / 극한)
- **창고의 군수 구역**: 비축 목표 관리, 비상 키트 포장, 필요한 곳에 재배치 (운반 시간·분산 보관 공간이 대가). 군수 담당은 먼저 기존 승무원의 겸직으로
- **복구 후 정리와 정상화**: 임시 배선 철거, 간이침대 회수, 부품 재활용, 폐쇄 구획 재사용을 작업으로 — 물리적 임시 시설은 치워도 연대기와 흉터는 남는다
- 급수 본관이 끊겼을 때 물통으로 재배대에 물을 나르는 일 (운반 작업과 비용)
- 시험: **기본 운영**과 **극한 생존**의 기준을 따로 둔다. 물자 부족 60일의 실패(6시드 중 2)가 피할 수 없는 소모전인지, 비축·격리·복구 선택을 잘못한 것인지 가른다
- 완료 기준: 반복 사고 뒤 비축이 회복되는 조건과 무너지는 조건을 기록으로 설명할 수 있다 (예: 운석 배는 얼음 20개를 녹여도 공기 탱크 6% — 반복 감압의 소비가 보충을 넘는다)
