> 함장 요청 (10-25) 그대로: "지금 ui ux 상으로 할 수 있ㄴ게 너무 없어 직접 사고를 일으킬 수 있는 기능을 넣어주고 게임 내의 기체나 배선 이런것으루제외한 모든 오브젝트를 클릭해서 그 오브젝트의 설명 상태 이런거를 볼 수 있게 해주고, 현재 사람들의 상태나 주컴퓨터, 로봇, 드론들의 상태는 따로 아주 자세한 탭을 만들어서 무슨 생각을 하는지 어떤 상태인지 특히 주컴퓨터는 현재 무슨 예측을 하는지 어떤 상태인지 어느 정도의 전확성을 가졌는지 등등 ui ux 개선 진행해"

> 자리는 1920×1080 · 배율 1의 논리 점이다 (UI.md §1.5). 옛 게임 판은 고치지 않는다.

## 0. 원칙 (UI.md §0을 잇는다)

1. **함장의 손은 바깥에서 오는 입력이다.** 월드 엔진이 결과를 셈한다. 이야기꾼이 아니다 — 사람 · 로봇 · 주컴퓨터의 마음을 직접 건드리지 않는다. 그들은 센서 · 본 것 · 들은 것으로만 안다.
2. **이미 있는 월드 길만 쓴다.** 새 법칙은 없다. 비공개 법칙의 문을 여는 얇은 문 (§2.4 표)만 더한다.
3. **결정론.** 손은 틱 사이에 받아 두고 **다음 틱의 맨 처음**에 차례대로 적용한다 · 장부에 찍는다 · 다시보기와 저장이 같은 틱에 같은 손을 재현한다 · 1코어 = 4코어.
4. **원인 마디는 '함장이 일으킨 …'** (게임 글). 연출 · 사슬 판 · 장면 판이 그 뿌리를 그대로 읽는다.
5. **살펴보기 · 자세한 판 · 예측 장부는 화면 값이다.** 세계 · 결정론 · `Lab --fingerprint`는 그대로다 (`--fingerprint`는 LiveShow를 쓰지 않는다).
6. **정직하게.** 함장 화면은 참을 보인다 (관객). 주컴퓨터 · 사람이 아는 것은 따로 적고 차이를 보인다 (상태 띠 '주컴퓨터는 아직 모른다'와 같은 결).
7. **마우스만으로.** 키는 덧붙임이다 (괄호에 적는다). 누름 · 놓음이 같은 손잡이일 때만 한다. 오른쪽 누르기 = 뒤로.
8. **60프레임.** 판 줄은 열린 판 · 연 사람 하나만 짓는다 · 비싼 표는 화면 0.5초에 한 번 · 올림 셈은 한 점 (§10).
9. **게임 글에 개발 용어 없음** · 지휘자는 '함장' · 화면 글자는 Pretendard에 있는 것만 (✕ ▾ ✔ ≡ ◀ 쓰지 않음 — 꺾쇠 · 세모 · ×는 도형).

### 2.2 뺀 것 (까닭)

| 뺀 것 | 까닭 |
|---|---|
| 사람 몸을 겨눠 다치게 하기 (`Life.Strike` 등) | 함장의 손은 세상의 일을 일으킬 뿐 사람을 겨누지 않는다. 던진 물건 · 폭발에 사람이 다치는 것은 월드(⑦)가 셈한다 |
| 병 · 마음 · 다툼 · 소문 | 함장 결정 '무엇도 사람의 마음을 직접 건드리지 않는다' · 이야기꾼 없음 |
| 기체를 칸에 바로 넣기 | 원인이 없는 기체는 월드 길이 아니다 — 기체 샘은 관 · 봉함 고장으로 (7 · 8 · 5) |
| 차단기만 떨어뜨리기 | 월드에 바깥 문이 없다 (`Trip`은 합선의 결과) — 전선 끊기가 합선 → 차단기를 낸다 |
| 발생기 '끄기' 스위치 | 뒤로 미룸 (§11 질문 4) — 끈 원인이 원인 사슬에 남는지 먼저 본다 |

### 2.3 흐름 (마우스만으로)

1. 둘째 줄 탭 **[사고]** (X) → 오른쪽에 사고 판.
2. **줄을 누르면 겨눈다.** 크기 칩 [작게][보통][크게]을 누르면 그 크기로 겨눈다 (기본 보통 · 갈래마다 마지막 고른 크기를 기억한다).
3. **겨누는 동안 세계 위:**
   - 커서는 십자. 커서 칸에 겨눔 고리와 이름표가 따라온다.
   - 되면 호박색: '불씨 · 보통 — 식당 침대 (매트리스)'. 안 되면 빨강: '여기는 안 된다 — 외판 칸을 누른다'.
   - 선 · 관 갈래(3 · 4 · 7 · 8)는 '선과 관' 겹쳐 보기가 저절로 켜진다 (그만두면 예전 겹쳐 보기로).
   - 운석은 바깥에서 그 칸까지 오는 줄 · 구름은 누를 쪽에서 배로 오는 화살표.
4. **세계를 누르면 (끌지 않고 놓으면) 일어난다.** 한 번 누르면 한 번 — 겨눔이 풀린다. 또 하려면 줄을 다시 누른다.
5. **밀어 던지기:** 물체 위에서 눌러 끌고 놓는다. 끈 쪽 = 쪽 · 끈 길이 = 빠르기 (0.5칸에 1m/s · 8m/s까지). 끄는 동안 화살표와 '3.2m/s' 이름표.
6. **겨누지 않는 갈래 (6 · 10 · 15):** 줄을 누르면 겨눔 줄에 **[일으키기]**. 누르면 곧 받아 둔다.
7. **그만두기:** 오른쪽 누르기 · 겨눔 줄 [그만두기] · 같은 줄 다시 누르기 · Esc.
8. **카드에서:** 살펴본 물건 카드의 **[사고 ›]** — 그 물건에 맞는 첫 갈래로 대상이 정해진 채 겨눈다 (침대 → 불씨 · 산소 발생기 → 고장 · 문 → 끼임 · 컵 → 밀어 던지기). 겨눔 줄 [일으키기]로 한다.
9. **알림:** '함장이 일으켰다 — 불씨 (식당 침대)' 3초 (누르면 사고 판). 사고 판 아래 '방금 일으킨 것' 다섯 줄 (누르면 그 자리로).
10. **멈춤 · 출항 준비 중:** 받아 두고 겨눔 줄에 '기다리는 손 2 — 시간이 가면 일어난다'. 세계가 다음 틱을 돌 때 그 틱 맨 처음에.

### 2.4 세계에 들어가는 길 — `Hand` (함장의 손)

새 파일 `engine/ShipEngine/Outside/Hand.cs`. 엔진이지만 13층 바깥의 **바깥 입력**이다 — ②③④⑤⑥을 부르고 (위는 요청만) ⑦⑧⑨⑩은 모른다. 화면(LiveShow)만 이것에 손을 넣는다.

```csharp
public enum HandKind : byte { None, Fire, Hole, PowerCut, DataCut, Fault, Gravity, WaterLeak, CoolantLeak, DoorJam, O2Drift, Blast, Shove, Rock, Cloud, Flare, Route }

[StructLayout(LayoutKind.Sequential, Pack = 1)]
public struct HandOrder
{
    public long Tick;        // 일어난 틱 (받을 때는 0 — Step이 찍는다)
    public int Seq;          // 받은 차례 (1부터 · 세계마다)
    public HandKind Kind;
    public byte Size, Part;  // 크기 0~2 · 부품 (고장)
    public int Cell, Obj;    // 칸 · 대상 (장치 · 문 · 물체 Id · 항로 번호 · 구름 갈래)
    public float X, Y;       // 쪽 · 빠르기 (밀기 m/s · 운석 · 구름이 오는 쪽)
    public int Cause;        // 붙인 원인 마디 (0: 헛손 — 그사이 대상이 사라졌다)
}

public sealed class Hand : IEngine   // Name "함장의 손" · Phase.Outside · Every 1 · Offset 0
{
    public readonly List<HandOrder> Waiting = new(), Done = new();   // 찍는다 · Done은 256까지 (다시보기 고리 1시간치보다 넉넉)
    public int Seq;
    public const int MaxWaiting = 8, Keep = 256;
    public bool Enqueue(HandOrder o);                       // 틱 사이에만 (작업 스레드) · Seq = ++Seq · 가득이면 거짓
    public static string Why(Sim sim, in HandOrder o);      // "" 되면 · 아니면 안 되는 까닭 (화면 미리 보기와 Step이 같은 판정 — 읽기만)
    public void Step(Sim sim, double dt);                   // Waiting을 Seq 차례로: Tick = sim.Tick → Why → 원인 마디 → Apply → Done
    private void Apply(Sim sim, in HandOrder o, int cause); // §2.1 표의 월드 길
    public static string Text(Sim sim, in HandOrder o);     // 원인 글 '함장이 일으킨 …'
    public void Save(StateWriter w) { w.List(Waiting); w.List(Done); w.I32(Seq); }
}
```

`Why`의 판정 (게임 글):
- 불씨 · 폭발: 배 안 빈 칸 (`L.IsSpace` · 바깥 · 떨어져 나간 칸 아님) — 아니면 '배 안을 누른다'. 탈 것이 없거나 산소가 옅으면 되지만 이름표에 '탈 것이 없어 곧 꺼질 것이다' · '공기가 옅어 붙지 않을 것이다'.
- 외판 구멍: `L.Kind == Wall && L.Hull` · 이미 그만큼 뚫렸으면 '이미 뚫렸다'.
- 선 · 관: 그 칸에 그 선 (`LineAt` 비트 · `OnData`) · 이미 끊겼으면 '이미 끊겼다'.
- 설비 고장: 설비 칸 · 그 부품이 있다 (`dev.Has(p)`) · 이미 망가졌으면 '이미 망가졌다'.
- 문 끼임: 문 칸 · 이미 끼었으면 '이미 끼었다'.
- 운석 · 구름 · 별 폭발: 행성에 내려앉았으면 (`Outside.Planet != null`) '행성 위에서는 오지 않는다'.
- 밀기: 그 물체가 있고 막음 · 우주 · 낌(상태 5 · 6 · 7)이 아니다.
- 받아 둔 뒤 그사이 대상이 사라지면 (불이 다른 것으로 · 물체가 우주로) **헛손**: 원인 마디 없이 Done에만 · 화면 알림 '그사이 대상이 바뀌어 일으키지 못했다'.

### 2.5 결정론 · 저장 · 다시보기

- **길**: 메인 스레드 → 명령 줄 `_cmds` → 작업 스레드가 틱 사이에 `Hand.Enqueue` → 다음 `Sim.Step` 맨 처음 `Hand.Step`이 Seq 차례로 적용 → 같은 틱에 월드 엔진들이 결과를 셈한다.
- **1코어 = 4코어**: 손은 한 줄로 적용 (병렬 없음). 그 뒤 엔진들은 지금처럼 결정적이다. 같은 장부면 바이트가 같다.
- **복제는 함장의 다음 손을 모른다**: 주컴퓨터 일꾼 · Rehearse · 연출 미리 보기는 틱 가운데에서 찍는다. 기다리는 손은 그때 늘 비었다 (틱 처음에 비운다). '아는 것으로만'과 맞는다.
- **저장**: `Waiting` · `Done` · `Seq`를 찍는다. 기다리는 손이 있는 채 찍고 되살려도 다음 틱에 같은 손이 난다.
- **다시보기**: 되살린 세계(고리 찍기 t0)의 `Done`에는 t0 앞의 손만 있다.
  - `LiveShow.StartReplay`가 산 세계 `Hand.Done` 가운데 `Tick ≥ t0`인 것을 `_replayHand`에 옮겨 둔다.
  - `Advance`가 되살린 세계를 한 틱 돌리기 전에 `w.Tick == o.Tick`인 손을 `Enqueue`한다 (`Seq`는 같은 차례로 다시 매겨져 같아진다).
  - 그래서 같은 틱 · 같은 차례 · 바이트까지 같다 (법칙 §8 L3).
- **연출 미리 보기**: 사실 수가 어긋나면 다시 복제한다 (이미 있음 — `DirectorForesight` 머리글이 '함장의 손'을 적어 두었다). 손을 쓴 틱에 복제 한 번 더 (새뜰 약 5ms · 다른 코어).
- **항로 고르기도 손으로** (`HandKind.Route` · `Obj` = 항로): `ChooseRoute`는 판정 · 알림만 하고 `Hand`에 넣는다 (§7 결함 1).
- **지문**: `--fingerprint`는 빈 손 장부 바이트만큼 바뀐다. `--fingerprint flow`는 같다 (손이 없으면 일어나는 일이 같다).

### 2.6 누가 어떻게 아나 (판단 엔진 — 아는 것으로만)

- 카메라: 손을 쓰면 손 카메라 8초 (`_handAt = _anim` · 그 자리에 머문다) → 그 뒤 연출이 맡는다. 바깥 갈래(운석 · 구름 · 별 폭발)는 맡기지 않는다 (잡히거나 닿을 때 연출이 간다).
- 빠르기: 따로 늦추지 않는다 — 연출이 조짐 · 위험에 늦춘다. 고정 빠르기면 그대로 (함장이 고른 것).
- 화면 표: 누른 칸에 0.5초 호박색 고리가 퍼진다 · 기다리는 손은 그 칸에 깜빡이는 점.

### 3.2 누르기 차례 · 맞히기 (32 · 16 · 8도트)

**여유** `pad = max(0.12, 10 / cellPx)` 칸 (`cellPx` = 화면 너비 픽셀 ÷ `CamW`) — 화면 10픽셀이다.
- 32도트 (40칸 보기 · 칸 48px): 0.21칸. 16도트 (90칸 · 21px): 0.47칸. 8도트 (130칸 · 15px): 0.68칸.

**차례** (한 점에 둘이 겹치면 앞의 것):

| 차례 | 갈래 | 맞음 |
|---|---|---|
| 1 | 사람 | `Nearest(Spots)` 0.9칸 — **0.45칸 안이면 늘 먼저** · 0.45 ~ 0.9칸이면 커서가 물체 · 가구 상자 **안**이 아닐 때만 |
| 2 | 로봇 · 드론 | 같다 — 사람과 겹치면 사람 (같은 거리 + 0.25칸까지 사람) |
| 3 | 물체 (물건 · 조각 · 뜯긴 가구 · 문짝) | 그린 자리 상자 (도트 꼴 `W × D` ÷ 32m · 자세 `Th` · `Painter.PropPose`의 넘어짐 옮김 · 높이 `z × 16도트 = z/2칸` 위로) + pad. 여럿이면 **발자국이 작은 것** (탁자 위 컵 > 접시 > 탁자) |
| 4 | 가구 · 설비 | 커서 아래 칸 ∈ `Furniture[f].Cells` (제자리인 것만) |
| 5 | 문 | `L.DoorAt[칸] ≥ 0` |
| 6 | 벽 · 외판 | `Kind == Wall` |
| 7 | 바닥 (고인 물 · 가루 · 방) | 배 안 빈 칸 |
| — | 바깥 · 우주 | 없음 → 놓기 |

- **떨어져 나간 조각 위**: `LiveShow.CellUnder(x, y)` — 몸 b ≥ 1의 그린 자세(`PoseDrawn`)를 거꾸로 돌려 그 칸이 그 몸의 칸인지 본다 (`BodyOf`). 아니면 배(몸 0)의 칸.
- **사람 우선 규칙**은 `LiveShow.Nearest`를 고친다 (사람 · 로봇이 겹치면 사람). 올림 · 누름이 같은 셈이라 예전 시험 '세 점에서 Nearest == SelectAt'은 그대로 통과한다.

### 3.3 올림 · 테두리 · 누름

- 메인 스레드는 세계 위에서 마우스가 칸 0.02 넘게 움직이면 `SetHoverAt(cx, cy)`를 보낸다. 작업 스레드가 다음 장에 `PickAt`로 **한 점만** 셈해 `f.HoverLook` (열쇠) · `f.HoverInside` · `f.HoverAtX/Y` · 이름 · 테두리를 싣는다.
- 테두리: 올린 것은 흰 1px (60%) · 고른 것은 노랑 1.5px (고른 사람 고리와 같은 빛). 물체는 돌린 네모 · 가구는 칸들을 두른 네모 · 문 · 벽 · 바닥은 그 칸.
- 0.35초 머물면 풀이 글 '식탁 — 누르면 살펴본다'.
- **누름** (끌지 않고 놓음): 사람 · 로봇 (§3.2 규칙) → `SelectAgent` / 아니면 `f.HoverLook`가 있으면 `Inspect(열쇠)` — 올린 것과 누른 것이 늘 같다. 단, 누른 자리가 `HoverAt`에서 pad 넘게 떨어졌으면 (빠른 손) `InspectAt(cx, cy)` (작업 스레드가 그 자리로 다시 셈) / 아무것도 없으면 `Release()` + `LookClose()`.
- 커서: 누를 것 위 = 손 · 겨누는 중 = 십자 (안 되는 칸은 금지 모양) · 끄는 중 = 끌기.

### 3.4 화면만

- 살펴보기는 읽기만 한다. 새 읽기 (`Network.BrokenCause` · `Network.OnData` · `Structure.HurtShare`)는 값을 셈해 돌려줄 뿐 상태를 쓰지 않는다.
- 시험: 살펴보기를 켠 화면과 쌍둥이 세계의 찍기 바이트가 같다 (§8 V4).

- 세계 밖 · 연출처럼 틱마다 읽기만 한다: `LiveShow.Advance`의 틱 고리 (`d.Observe(w)` 뒤 · 산 세계만) · `FastForward` 고리.

  - 맞댈 때가 된 것을 실제와 맞대어 '지난 예측'으로 옮긴다.

### 4.6 펼침 · 넘기기 · 열쇠

- 자세히의 줄도 `PanelRow` · `LayoutPanel` 그대로 (넘김 막대 · 휠 · 막대 끌기).

## 7. 함께 고칠 결함

1. **항로를 바꾼 것이 다시보기에 남지 않는다.** `ChooseRoute`가 세계(`o.Route` · `PlanVoyage` · 원인)를 곧바로 바꾼다. 출발 점화 전 20분 안에 항로를 바꾸면, 그 앞 찍기에서 되살린 다시보기는 옛 항로 · 옛 점화로 돈다 (점화 가속에 물건이 다르게 미끄러진다). → 손 장부의 `Route`로 (U3 · 규칙 고치기 전 빨강).
2. **판단 일지 여덟 칸** — 자세한 판에서 몇 분이면 밀린다 → 32칸 (`Mind.cs` 346 · 찍지 않는다 · 화면만 · 136명 × 32칸 약 200KB) (U5).
3. **사람 판 줄을 누르면 판이 닫혀** 자세히 볼 길이 없다 → 자세히 + 따라가기 (U1 · 바뀐 시험 하나: '마우스 판 열쇠').
4. **로봇 · 드론이 사람 판 끝에 섞인다** → 로봇 판 (U1).
5. **`Gauge.Short`가 없다** (UI.md §2 '상태 띠가 탭 왼쪽을 넘으면 칸마다 Short') — 탭이 일곱이 되면 1366×768에서 더 잘린다 → 더한다 (U1).
6. **화면 찍기 플래그**: 과제 글의 `--view=`는 이미 '확대 칸 수'다 → 겹치지 않게 `--ui=장면` · `--shot=이름` (U1).
