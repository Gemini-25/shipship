# 개발 과정 (2026-10-16 새로 정함)

## 왜 바꿨나
- 전체 회귀 52번을 세어 보니 시험 136개 중 **90개가 통과했다 실패했다 오락가락**했다 (늘 통과 40 · 늘 실패 6).
- 장면 시험은 "하루를 보낸 배 전체"를 몇 시간 통째로 돌린 뒤 결과를 문턱으로 본다 → 어디서든 행동이 조금 바뀌면 역사가 갈려 상관없는 시험이 뒤집힌다.
- 기능 하나마다 10~30개가 뒤집히고, 그걸 하나씩 "진짜냐 운이냐" 가리는 데 개발 시간 · 토큰의 대부분이 들었다.
- CPU는 더 짜낼 게 적다: .NET 실행 설정 7가지는 오차(±10%) 안 · 프로파일은 평평(가장 큰 항목 7%) · 첫날 배 캐시로 −17%.

## 시험의 세 층 (`tools/tests/tests.txt`)
| 층 | 무엇 | 실패하면 |
|---|---|---|
| **rule** 규칙 시험 (`--ruletest`) | 작은 배에서 규칙 하나씩 — 몇 초 · 결정적 | **막음** — 진짜 버그 |
| **core** 핵심 장면 15개 | 회귀 52번 내내 통과하던 것 | **막음** — 바로 조사 |
| **scene** 장면 시험 (나머지) | 이야기 장면 · 통계 | 막지 않음 — 기준(`tools/tests/baseline.txt`)에선 통과하던 장면이 실패하면 다른 시드 둘(11 · 23)로 **지금 코드와 기준 커밋을 함께** 다시 돌려, **그 시드에서 기준은 통과하는데 지금은 실패할 때만 조사** (지금도 통과 → 운 · 기준도 실패 → 시드 7에 맞춘 장면) |

- 끄는 시험은 없다. 장면 시험도 늘 돌고 결과표에 남는다.
- 새 기능 · 고친 버그마다 규칙 시험을 하나씩 더한다 (`tools/Headless/RuleTests.cs`). 규칙은 고치기 전 코드에서 실패하는지 확인한다.

## CI가 빠르게 도는 까닭 (`.github/workflows/tests.yml`)
- 빌드 한 번 → 10조각 동시에 (조각마다 4개씩 — 러너 CPU 4개). 조각은 **CI가 잰 시험별 초**로 오래 걸리는 것부터 고르게 나눈다 (`tools/tests/tests.txt` 셋째 칸).
- 같은 가지는 **한 번에 한 실행만** — 잇달아 푸시해도 도는 것은 끝까지, 기다리는 것은 가장 새 커밋 하나만 남는다 (실행 셋이 겹쳐 조각이 3분씩 줄 서던 일).
- growthtest(통계 장면 · 20일 항해 16번)는 시드마다 자식 프로세스로 나눠 동시에 (`tools/Headless/ChildRuns.cs`) — 1156초 → 약 420초. CPU를 다 쓰니 조각 하나를 혼자 쓴다 (tests.txt 넷째 칸 `solo`).
- 시험별 초는 한 번 잴 때마다 ±30% 흔들려 (mindcaretest 130 → 192초) `retime.py`가 지금 값과 반씩 섞는다.
- 새 실패 재확인은 많아야 5조각에 묶어 (조각마다 지금 코드 · 기준 커밋 × 시드 둘 = 4개 동시) · 기준 커밋 빌드는 캐시.
- 러너는 ubuntu-24.04로 고정.
- **지금 바닥은 growthtest**: 조각을 혼자 써도 410초 — CPU 4개를 다 쓰는 일감(미리내호 약 380일치: 20일 항해 16번 + 44일)이라 러너 하나로는 더 못 줄인다.
  더 줄이려면 시험 내용(시드 8개 통계)을 바꾸거나 러너 여럿에 나눠 모아야 해서 멈췄다. 전체 = 빌드 약 80초 + growthtest 조각 약 430초 + 정리 약 25초.

## 도구
- `tools/quick.sh [출력 폴더] [더 돌릴 시험 ...]` — 빠른 묶음
- `tools/ci/last.sh [--times] [--run ID] [--wait]` — 이 가지의 가장 최근 CI 결과 몇 줄 (`--times`: 시험별 초 한 줄 · `--wait`: 지금 커밋의 실행이 끝날 때까지 기다림 — 푸시 뒤 백그라운드로)
- `tools/ci/retime.py < 시간줄` — 시험별 초를 tests.txt에 (`tools/ci/last.sh --times | python3 tools/ci/retime.py`)
- `tools/ci/run-tests.sh 목록 출력 [동시에] [시드] [뒤붙임]` — 시험 여러 개를 돌려 이름별 파일로
- `tools/ci/shard.py tests.txt 조각 조각수` — 오래 걸리는 것부터 고르게 나눔
- `tools/ci/summarize.py --results 폴더 [--recheck 폴더] [--plan json] [--md 파일] [--only rule,core] [--times]` — 한 장 요약 (빨강이면 종료 코드 1)
- 첫날 배 캐시는 기본 켬 (`SHIPSIM_WARM=0`으로 끔) · 켬/끔 출력이 137개 모두 같음을 확인했다. `SHIPSIM_WARM_REPORT=1`이면 몇 번 되살렸는지 · 새로 돌린 시간을 찍는다 (CI 요약에 합계).
