# 설계 방향 결정 (v12.1 이후 토론)

분야별로 토론해 정한 것. 구현 순서와 세부는 ROADMAP.md에서 이 결정을 따른다.

## 1. 게임의 정체성과 플레이어 역할

| 질문 | 결정 |
|---|---|
| 플레이어는 누구인가 | 관찰자. 중앙 컴퓨터 권한으로 개입할 수도 있다 (컴퓨터 등급 = 개입 범위). **플레이어가 손대지 않아도 중앙 컴퓨터는 스스로 판단해 돌아간다** |
| 개입 수준 | 기본은 **사고 일으키기만**. 방침(비축·우선순위·회의 결정)과 장치(격벽·댐퍼·차단기·경보·드론) 조작까지 가능하지만 선택 사항. 사람에게 직접 지시는 없다 |
| 한 판의 목표 | **끝없는 샌드박스가 기본**. 시나리오 도전은 **캠페인**으로, 세대선(수십 년·인원 교대)은 캠페인의 일부로 |
| 끝난 뒤 | 항해 기록(연대기) 요약 + 같은 배로 다음 항해 (흉터·늙은 설비·승무원 기억이 남는다) |
| 플레이어가 아는 것 | **모든 수치가 보이는 것이 기본**. 센서 화면(감지기가 아는 값·측정 시각·교정)·배선 화면·배관 화면 등을 따로 볼 수 있게 |
| 재미의 중심 | ① 재난이 번지고 복구되는 연쇄 (최우선) → ② 배가 스스로 고쳐 가는 설계·개조 (자동으로) → ③ 사람 이야기 · 생존 관리 |

## 2. 배의 설비·기반 시설

| 질문 | 결정 |
|---|---|
| 이중화 | **배 크기별 차등이 기본** (작은 배: 간선 하나 · 큰 배: 링 배선 + 비상 모선). 사고를 겪으면 **승무원이 스스로 개선**한다 (회의 → 반대쪽 간선 증설 공사, 끊긴 구간 임시 우회 케이블) |
| 망의 세밀도 | **3단계**: 간선(방 사이) → 방마다 분전함·차단 밸브 → 설비 인입선. 문제가 생긴 방만 차단·격리할 수 있다 |
| 망 종류 | **전부**: 전력 · 급수 · 환기 + 데이터망(감지기·컴퓨터·문 제어) + 냉각수·산소관 통합 + 오수·폐기물 관 + 추진제 연료관 |
| 설비 속 부품 | **핵심 설비만 부품 단위** (냉각 펌프·산소 발생기·정수기·배전반·주 컴퓨터·에어록·원자로): 베어링·씰·임펠러·기판·모터마다 상태. 나머지는 고장 종류 + 부품 아이템 |
| 환경 상호작용 | **전부, 많을수록 좋다** (아래 목록) |
| 중앙 컴퓨터의 설비 판단 | 부하 조절 · 재가동 순서 · 우회 배전 · 격리를 스스로 하고 **판단 근거를 말한다**가 기본. **등급이 높을수록 기능이 늘어난다** (낮은 등급은 틀린 판단도 한다) |

### 환경·설비 상호작용 목록
토론에서 나온 것:
- 물 ↔ 전기: 누수·습기 → 누전·단락 → 불
- 결로: 찬 배관 + 습한 방 → 물방울 → 누전
- 기동 전류: 큰 설비 동시 기동 → 차단기 트립 → 재가동 순서
- 열 부담: 발열 설비 증설 → 냉각 부족, 뜨거운 방은 설비 수명 감소
- 먼지·기름때 → 필터 막힘, 냉각 효율 저하
- 소음·진동 → 잠의 질

추가 (Claude 제안):
- 부식: 습기 + 금속 → 배관·이음부·외벽 부식 → 미세 누설
- 진동 공진: 떨리는 펌프 + 풀린 받침 → 옆 설비 볼트까지 풀림
- 열팽창: 급격한 가열·냉각(재가동·화재 진압 직후) → 이음부 누설, 워터해머
- 동결: 진공에 노출된 배관·냉각 과다 → 얼어서 파열
- 방사선: 원자로 차폐 손상 → 기판 오류(비트 뒤집힘)·감지기 잡음, 승무원 피폭
- 전자기 간섭: 고출력 설비 옆 데이터망 → 헛경보·통신 끊김
- 접지 불량 → 감지기 잡음, 감전
- 정전기: 건조한 공기 + 짙은 산소 → 불꽃
- 곰팡이·미생물: 습기 + 온기 → 덕트·필터 곰팡이 → 호흡기 질환, 수경 병해
- 윤활유·냉각수 누유 → 바닥 미끄러움(넘어짐·부상) + 불쏘시개
- 그을음·연기 → 광학 감지기 오염 → 화재 감지 늦음
- 배터리 과충전 → 부풂·수소 가스 → 환기 필요
- 냉매 누출 → 산소 치환(질식) · 차가운 방
- 물때·스케일: 경수 → 열교환기·배관 좁아짐 → 유량 감소

## 6. 배 설계와 공간

| 질문 | 결정 |
|---|---|
| 방 종류 체계 | 필수 / 표준 / 대형 전용 3단계, **방 종류는 다양하게**. 전용 방이 없는 기능은 다른 방이 대신 맡고 대가를 치른다 |
| 배를 어떻게 만들까 | **손으로 그린 대표 배(캠페인) + 시드로 절차 생성하는 배(샌드박스)**. 절차 생성은 필수 방을 보장하고 크기에 따라 전용 방·구획·이중화 수준이 달라진다. 모양은 작은 배 일자형, 큰 배는 양쪽 날개형·고리형·모듈 이음형 등 여러 가지 (모양마다 급소·대피 동선이 다르다) |
| 증축·개조 | **전부**: 방 용도 변경 · 나누기·합치기 · 선체 밖 모듈 공사(선외 작업) · 잔해·난파선 모듈 회수. 승무원 회의가 정하고, 플레이어는 원하면 승인·거부만 |
| 인접성 | 이웃 방으로 **소음·진동·열·냄새·방사선이 번진다** (원자로 옆 침실은 잠을 설치고 피폭, 의무실이 에어록 가까우면 부상자 이송이 빠름) |
| 구획 | **배 크기별 차등**: 작은 배는 방 단위, 큰 배는 기밀·방화 구획마다 방화문·비상 격벽·구획 분전반 |
| 선체 바깥 | 외부 설비(방열판·안테나·센서 마스트·태양전지·외부 연료 탱크·도킹 포트). 망가지면 **드론이 먼저, 큰 수리는 사람이 선외 작업** |

| 대형 | 기록 보관실 | 함선 연대기·교훈 보관 (교훈 전수, 다음 항해로 기억) | 주 컴퓨터 — 컴퓨터가 멎으면 기록도 |
| 대형 | 명상실 | 혼자 있는 공간 (공황·트라우마 회복) | 침실 — 사생활 없음 |
| 대형 | 셔틀 격납고 | 셔틀 (잔해 회수·탐사·탈출) | — |

## 3. 사고·재난과 난이도

| 질문 | 결정 |
|---|---|
| 난이도 구조 | **성격이 다른 이야기꾼 여러 명 + 난이도 단계** (꾸준형·몰아치기형·무작위형·시험관형 — 시험관형은 배의 급소를 노린다) |
| 이야기꾼의 태도 | **이야기꾼마다 다르다**. 기본은 "회복할 틈은 주되 완전히 회복하기 전에". 보는 값: 회복 여력(예비 부품·예비 설비·움직일 수 있는 인원·전력·산소·물·식량 여유) + 연쇄 피해(진행 중인 사고·끊긴 망·쓰러진 사람·미뤄 둔 정비) |
| 사고의 원천 | **외부 사고는 이야기꾼이**, 설비·사람·생물 사고는 **배의 상태에서 저절로** (정비를 미루면 고장, 습하면 곰팡이, 지치면 실수). 이야기꾼은 저절로 생긴 사고도 연쇄 평가에 넣는다 |
| 사고 종류 | **전부 넣는다, 연쇄를 잘 일으키는 것부터** (배관 파열·침수 → 원자로 냉각 상실 → 컴퓨터 오판단 → 전염병 …) |
| 치명도 | **난이도마다 다르다**. 보통: 대형 사고 하나는 사망 0, 2~3개가 겹치면 1~2명, 대응 실수까지 겹치면 전멸 가능. 어려울수록 회복 여력(시작 부품·예비 설비)도 준다 |
| 사고의 꼬리 | **단계 복구(응급 → 임시 → 정식, 며칠~몇 주) + 영구 흉터 + 배가 배운다** (개선 공사·교훈·훈련·이중화 증설) |
| 사고 도구 | **사고 메뉴**: 종류·위치·크기를 골라 일으킨다 |

### 사고 목록
토론에서 나온 것:
- 외부: 미세 운석 소나기, 성간 먼지 구름, 태양 플레어(방사선 + 전자기 교란), 떠도는 난파선 접근
- 설비: 원자로 냉각 상실, 원자로 출력 폭주, 냉매 누출, 배관 파열·침수, 에어록 오작동, 추진제 누출·엔진 폭주, 구조 피로 균열, 자동 소화 오방출
- 컴퓨터: 데이터망 오류, 컴퓨터 오판단, 경보 폭주, 기록 손상
- 생물: 전염병, 식중독, 정수 오염, 수경 병해, 곰팡이, 조류 배양 오염
- 사람: 과로 실수, 절차 생략 사고, 공황, 다툼·폭행, 폭동, 핵심 인력 사망 뒤 기능 공백
- 환경: 동결, 방 과열, 방사선 누출, 산소 과잉

추가 (Claude 제안):
- 덕트 화재: 덕트 속 먼지·기름때에 불이 붙어 덕트를 타고 먼 방까지 번진다
- 분전함 전기 화재: 누전·과부하 → 그 방 차단 → 구획 정전
- 연쇄 차단기 트립: 재가동 때 기동 전류가 몰려 차단기가 줄줄이 떨어진다
- 수소 축적: 배터리실 환기가 끊기면 수소가 모인다 → 불꽃 하나에 폭발
- 가스 탱크 파열: 고압 산소·질소 탱크 → 파편 + 산소 과잉 또는 질식
- 하수 역류: 오수관 막힘 → 위생·질병·악취
- 냉동 저장고 정전: 식량 부패 → 식중독 또는 배급
- 재배 조명 고장: 작물 광합성 중단 → 며칠 뒤 식량
- 식량 해충: 창고 저장품 오염
- 배관 부식 → 물 오염(중금속) → 서서히 아픈 승무원
- 방열판 파손·동결 → 냉각 부족 → 원자로 출력 제한
- 선외 표류: 테더가 끊기거나 에어록 사고로 사람이 떠내려간다 → 드론·셔틀 구조
- 도킹 충돌: 보급 캡슐·셔틀이 도킹 포트를 들이받는다
- 로봇 오작동: 운반 로봇이 문을 막거나 엉뚱한 곳에 물자를 쌓는다
- 드론 충돌: 좁은 곳에서 드론끼리·설비에 부딪힌다
- 원심 중력실 불균형: 진동이 배 전체로 → 볼트 풀림
- 데이터망 과부하: 대형 사고 때 경보가 몰려 제어가 늦어진다

## 5. 자동화: 중앙 컴퓨터·로봇·드론

| 질문 | 결정 |
|---|---|
| 컴퓨터 등급 | **5단계가 기본** (I 경보 → II 자동 차단 → III 조정 → IV 추론 → V 지휘). 각 등급 안에서 **기능을 더 달 수 있다** (등급이 상한) |
| 컴퓨터의 약점 | **보수적인 자동화**: 피해는 막지만 손해가 크다 (필요 이상으로 넓게 차단·부하 차단·긴급 정지). **판단력 좋은 승무원이 중앙 컴퓨터를 수동으로 조종하면 더 효율적**으로 처리한다. 수동 조종이 없어도 웬만하면 컴퓨터가 나름 효율적으로 처리한다 (+ 전원·냉각·데이터망 의존, 틀어진 감지기, 기판 오류) |
| 컴퓨터와 승무원 | **모든 걸 컴퓨터가 할 수도, 사람이 수동으로 할 수도 있다. 누가 할지는 승무원이 판단한다** |
| 안전 조건·딜레마 | 기본은 **경고 + 카운트다운 후 대기**. 사람이 수동으로 **바로 닫아 버릴 수도** 있다. **사람 우선인지 배 우선인지는 승무원 회의가 정한다** |
| 로봇·드론 | 로봇(힘·느림)과 드론(빠름·약함) 역할 분리 + 종류 추가(의료 보조·소방·선외 수리 팔·수리 드론) + 핵심 개체는 부품 단위 상태 + **개체마다 이력과 버릇** + 컴퓨터가 지휘. 드론 속도 2~3배, 할 수 있는 일 확대, 협동 작업 |
| 로봇·드론 수 | 드론 정비고에서 **제작·증설**, 선외 표류·폭발로 **잃을 수 있고**, 잔해는 회수해 부품으로 |
| 컴퓨터의 말투 | 등급이 높을수록 맥락을 담은 설명. **승무원이 별명을 붙이고 관계(신뢰도)가 생긴다** ("할이 또 헛경보야") |

## 4. 승무원

| 질문 | 결정 |
|---|---|
| 신체 부위 부상 | **부위별**(머리·몸통·팔·손·다리·눈·귀·폐) — 다친 부위에 따라 할 수 있는 일이 달라진다 (손을 다친 정비사는 진단·감독). 원인별(화상·골절·열상·동상·방사선·감압병) + **의수·의족·인공 장기** (정비실 제작 → 의무실 수술) |
| 죽음과 그 뒤 | 시신 수습·안치소·추모·관계별 애도·역할 공백 + **기억** (추모실 명판, 그 사람 이름을 붙인 설비, 트라우마, 기일, 다음 항해로) |
| 성격과 습관 | 특성 + **설비·사고에 영향을 주는 습관** (공구를 제자리에 안 둠, 체크리스트 신봉, 지름길로 다님, 커피·야식·늦잠·정리벽) + **가치관**(사람 우선 / 배 우선 — 회의 투표) + **과거 경력**(전직 군인·의사·광부 → 기술·트라우마) |
| 생활 | 수면의 질(소음·진동·조명·온도·사생활) · 위생(샤워·세탁·선외복 세척) · 음식(조리 시각·보관 이력·식중독·배급 차등·입맛) — **판단력과 실수로 이어진다** (못 잔 사람은 절차를 건너뛰고, 굶은 사람은 예민해져 다툰다) |
| 관계와 갈등 | 대화·친밀도·전우 + 다툼·원한·파벌·연애·사수와 부사수 + 회의 파벌 투표 · 폭동. **갈등이 연쇄의 원인이 된다** (사이 나쁜 두 사람은 인수인계를 대충 하고, 상대 판단을 믿지 않고 다시 점검) |
| 전문 분야와 자격 | 기술 + **자격** (원자로 수동 조종·수술·컴퓨터 수동 조종 등). 교차 훈련으로 자격을 얻고, 비상시엔 자격 없는 사람도 시도하지만 실수가 잦다. 분야: 진단·계측, 보급, 안전, 설비 운전, 간호·재활, 선외 작업, 컴퓨터 수동 조종, 원자로 운전, 외과, 구조 대원, 교관 |
| 공동 작업과 돌봄 | 두 사람 작업(부품 지탱·차단기 확인·선외 감시·들것) + 돌봄(회복 간호·식사 가져다주기) + 손 다친 정비사는 진단·감독, 신참은 옆에서 배우며 거든다, **손발이 맞는 짝은 효율이 오른다** |
| AI 판단 스타일 | **사람다운 실수**(성격·피로·정보 부족) + **실수의 이유가 보인다** ("피곤해서 잔압 제거를 건너뜀") |

## 8. 보여 주기: 화면·정보·연출 — **가장 신경 쓸 분야**

> 지금까지 정한 디테일이 설정으로만 있지 않고 **실제로 체험되게** 하는 분야. UI/UX·그래픽·텍스처·정보를 보여 주는 방식을 가장 신경 써서 만든다.

| 질문 | 결정 |
|---|---|
| 인과 사슬 | 사고마다 원인 → 결과 사슬 그림 + **배 도면 위에 겹쳐** 어디서 시작해 어디로 번졌는지 움직이는 화살표, 되감기와 연결 |
| 누르면 나오는 설명 | 사전식 설명(하는 일·원리·필요한 것·멈추면·관리·위험) + **지금 이 물건의 이력과 연결**(어느 망에서 받고 무엇을 먹이는지) + 이 배에서 있었던 관련 사고 |
| 보기 화면 | **전부** (전력·급수·환기·데이터망·냉각수·산소·오수·연료·센서·온도·공기·구조·방사선·소음·위생·동선·작업), 단축키 전환 + **두 개까지 겹쳐 보기** |
| 카메라·하이라이트 | 사고 현장·중요 인물로 **자동 연출**(이동·확대·결정적 순간 슬로모션), 끌 수 있다 |
| 그래픽 | 지금 방식 + 조명·효과·배경 연출 강화 **+ 더 세밀한 픽셀 아트** |
| 소리 | 설비 상태음(닳은 베어링이 끽끽 — 플레이어도 전조를 듣는다) + 긴장도에 따라 바뀌는 음악 + 경보 종류별 소리 |
| 사람 표현 | 부상이 보인다(붕대·절뚝임) · 표정·자세 + 개인 일기 · 관계도 · 개인 이력 화면 |

### 보여 주기 원칙 (Claude 제안)
1. **숨은 시스템은 반드시 화면에 드러난다.** 새 시스템은 네 곳에 흔적을 남겨야 완성: 도면 위 표시 · 상세창 한 줄 · 보기 화면 · 인과 사슬의 고리
2. **정보는 세 층.** 한눈에(배 상태 신호등·사고 카드) → 한 번 누르면(상세창) → 파고들면(설명서·이력·사슬)
3. **그림으로 보여 줄 수 있으면 글보다 그림.** 부품 단위 설비는 분해도(베어링·씰·임펠러에 색), 사람은 몸 도해(부위마다 색), 망은 흐름 애니메이션, 컴퓨터 판단은 감지 → 추정 → 조치 → 대기(카운트다운) 흐름
4. **사고 카드**: 무엇이·어디서·지금 누가 대응 중인지. 누르면 인과 사슬로
5. **시간 막대**: 화면 아래 시간축에 사고·결정·사망 표시, 누르면 그 시점으로 되감기
6. **배는 늙고 흉터가 남는다.** 그을음·용접 자국·물때·빛바랜 칠이 영구히 남고, 방 종류마다 바닥·벽 재질이 다르다 (70종)
7. **색만으로 구분하지 않는다.** 색 + 모양·무늬 (색각 이상 대비), 글자 크기 조절
8. **많아져도 부드럽게.** 방 70종·효과가 많아도 60fps
